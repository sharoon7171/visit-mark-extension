SINGLE PURPOSE
================================================================================

SINGLE PURPOSE
----------------
Chrome Web Store: an extension must have a single purpose that is narrow and easy to understand.

VisitMark does one thing: make visited links easier to see with your highlight colors on web pages. The background service worker refreshes styling when tabs finish loading, you switch tabs, single-page apps change the URL, or history updates. It uses chrome.scripting to inject visited-link CSS and, when enabled, to read hrefs, match against Chrome history, and mark links in the page. The pop-up edits global and per-host colors and detection toggles, using tabs.query for the active tab hostname. chrome.storage (sync) saves settings; host permissions are http and https only. webNavigation and tabs events re-apply highlights per tab; history listeners refresh after visits are added or removed. No unrelated tools beyond visited-link styling.

Learn more: https://developer.chrome.com/docs/webstore/program-policies/quality-guidelines

================================================================================
HISTORY PERMISSION JUSTIFICATION
================================================================================

VisitMark uses the history permission for “Browsing history” visited-link highlighting, and you can disable that mode in the pop-up. When it is on, the extension reads hrefs from links already on the open page, normalizes them, and calls chrome.history.getVisits only for those URLs to see if they appear in your history; it never reads your full history list or unrelated addresses, matching stays on your device, and nothing is sent to the developer’s servers. chrome.history.onVisited and chrome.history.onVisitRemoved refresh on-page highlights when history changes. With browsing-history mode off, getVisits is not used for that feature (event listeners may still exist because the permission is declared).

================================================================================
SCRIPTING PERMISSION JUSTIFICATION
================================================================================

VisitMark uses the scripting permission only for visited-link styling on http and https tabs where Chrome allows injection. The extension uses chrome.scripting.insertCSS and removeCSS to inject or withdraw a stylesheet from your colors and toggles, and CSS is removed when highlighting is off or the page is not injectable. It uses chrome.scripting.executeScript only with bundled functions (not remote code): collect anchor hrefs for history matching when needed; apply a data attribute and color to matched links; clear marks on cleanup or setting changes. All work stays on your device; nothing is sent to the developer’s servers.

================================================================================
STORAGE PERMISSION JUSTIFICATION
================================================================================

VisitMark uses the storage permission to save your settings with chrome.storage.sync: global options (colors, on/off, detection toggles, which link patterns to include) and a map of per-website overrides. chrome.storage.onChanged listeners keep the pop-up in step when options change and let the background worker refresh highlights on open tabs. Values stay in Chrome (and sync to your Google account only if you use Chrome sync); VisitMark does not upload storage data to the developer’s servers.

================================================================================
TABS PERMISSION JUSTIFICATION
================================================================================

VisitMark uses the tabs permission so the background worker can find open tabs, detect when a tab finishes loading or you switch tabs, and apply or clear visited-link styling on the correct tab. It listens for tabs removed to drop internal tracking. The pop-up calls tabs.query for the active tab in the current window to read the hostname for “This site” controls. Tab URLs and page data are not sent to the developer; they are used only inside your browser for this feature.

================================================================================
WEB NAVIGATION PERMISSION JUSTIFICATION
================================================================================

VisitMark uses the webNavigation permission only for chrome.webNavigation.onHistoryStateUpdated on the top-level frame. Many sites are single-page apps that change the address without a full reload; that event tells the extension to re-run its highlight logic for the new URL so visited styling stays correct. It is not used for broad tracking of where you browse.

================================================================================
HOST PERMISSION JUSTIFICATION
================================================================================

VisitMark requests host permission for http://*/* and https://*/* so chrome.scripting can inject or remove visited-link CSS and bundled scripts on the web pages where the feature runs. Chrome requires host access for those APIs on ordinary sites. The extension does not use this access to scrape unrelated content or send page data to the developer’s servers; it is limited to applying visited-link appearance.

================================================================================
LONG DESCRIPTION (detailed listing field under screenshots)
================================================================================

VisitMark is a Chrome extension for anyone who wants to change visited link color in Google Chrome, make visited links easier to see, or replace faint default visited styling with a custom visited link highlighter. It applies your colors to normal page links so search results, docs, forums, dashboards, and shopping grids are quicker to read—you spend less time reopening the same URLs. If visited links disappear into the background on dark mode, high-contrast themes, or busy layouts, you can raise contrast with a global default and, when needed, a different color for a single website.

The extension keeps detection practical for real sites: use Chrome’s built-in visited state, optional browsing history matching for tricky single-page apps, or both. Global colors and toggles can follow your Chrome profile when you are signed in (Chrome sync). Per-site rules are saved by hostname. Styling targets regular anchor links in the visited state, including text inside the link, so highlights look like one unit. VisitMark only changes how visited links look; it does not redirect links, scrape pages for other purposes, or send your history or page content to the developer’s servers—settings live in Chrome storage (and sync) like other extensions.

Features

• Master switch (Visited link colors) for all sites
• Default highlight color for the whole web
• Detection: Browser visited state and optional Browsing history (independently toggleable)
• This site: enable or disable highlighting for the current hostname only
• Site-specific color and Color for this site when you need a local override
• Restore defaults for global options; Remove site settings to clear the current hostname
• Highlights refresh when tabs load, you switch tabs, history changes, or the URL updates without a full reload (SPAs)

Benefits

• Visited link customization you control instead of a single browser default
• Per-website visited link colors when one domain needs more or less contrast
• Fewer wrong clicks on long pages full of similar-looking links
• Globals can stay in sync across devices on the same signed-in Chrome profile
• Straightforward pop-up labels; one narrow job—visited link appearance

Use cases

• Google and Bing search results, SEO research, and long SERP-style pages
• E-commerce, price comparison, and affiliate grids where listings look alike
• Technical documentation, wikis, and knowledge bases with dense cross-links
• News, blogs, Reddit-style threads, and forums
• Work portals, ticketing systems, and internal tools
• Study and course sites; travel and booking flows with repeated card layouts

How to use

1. Install VisitMark from the Chrome Web Store, then pin the extension if you want fast access to settings.

2. Open a normal http or https page (the pop-up reads the current tab’s site for the “This site” section).

3. Under All sites, turn on Visited link colors. That is the main on/off switch for custom highlighting everywhere, unless a site opts out under This site.

4. Under Detection, leave Browser visited state on for typical links Chrome already marks as visited. Turn on Browsing history only if you want links whose URLs appear in your Chrome history to count as visited on the page (helpful when visited styling alone is wrong or delayed). You can use either mode or both.

5. Set Default color to a value that reads well on most sites you use. You can change it anytime; open tabs refresh when options save.

6. Optional: open a site that needs special treatment. Under This site, keep This site on so VisitMark applies here. Turn This site off to fall back to Chrome’s default visited look on that hostname only.

7. Optional: enable Site-specific color, then use Color for this site to override the default color on this hostname (useful for dark UI, brand-heavy pages, or accessibility).

8. If global options get messy, use Restore (under All sites) to reset the master switch, both detection toggles, and the default color. If only one domain is wrong, use Remove site settings to delete saved rules for the current site and return to global defaults.

9. Practical check: visit a page with many links, click a few, go back or scroll—visited links should show your color. If not, confirm Visited link colors is on, This site is on for that domain, and at least one detection mode is enabled.

Permissions in short: broad http/https access is required to inject visited-link styling; history is only used for optional matching you can turn off; storage holds your choices; tabs and webNavigation keep highlights on the right tab and catch SPA URL changes. Read Chrome’s prompt at install and adjust toggles to match what you are comfortable with. Shared computers: same profile shares the same extension settings; separate people should use separate Chrome profiles.

FAQs

Does VisitMark change where links go?
No. It only changes how visited links look.

Will it slow down Chrome?
It stays small and focused: CSS for visited links and, when you enable it, targeted history checks for links on the page.

How do I turn it off quickly?
Turn off Visited link colors for all sites, or turn off This site for one website.

Can I skip history-based matching?
Yes. Disable Browsing history under Detection and rely on Browser visited state only.

Can I use different visited link colors per website?
Yes. Enable Site-specific color on that site and pick Color for this site.

Does my browsing data get uploaded?
No. Work happens in your browser; settings use Chrome’s storage and optional Chrome sync per Google’s rules, not a separate VisitMark server for your history or page text.

Why might a link look wrong sometimes?
Redirects, caching, client-side routing, or site CSS can occasionally disagree with visited state or history. Switching detection options or adjusting per-site color usually fixes real-world cases without affecting other sites.
